# DEVISERA web — architecture, parité iOS et points d'intégration (14 septembre 2026)

L'espace web (`/app`) est le même produit que l'application iPhone : même base de
données, même authentification, mêmes services, mêmes formules, mêmes droits. Ce
document dit ce qui a été construit, ce qui est réutilisé, et où brancher Stripe.

## 1. Un seul écosystème

| Couche | Web | iOS | Partagé |
| --- | --- | --- | --- |
| Comptes, sessions | cookie httpOnly (`src/lib/auth/session.ts`) | jeton porteur (même table `sessions`) | `users`, `organization_members`, vérification email |
| Données | pages serveur → services (`src/server/services/*`) | `packages/shared/src/api-client.ts` → `/api/*` | Prisma, une seule base, isolation par `organizationId` |
| Formules et droits | `accessStateFor(SubscriptionSnapshot)` | idem | `packages/shared/src/plans.ts`, `entitlements.ts` |
| Consentement IA | `ai-consent-gate.tsx` | `AiConsentProvider` | `packages/shared/src/ai-consent.ts`, table `ai_consents` |
| Mise en route | `getHomeOverview` | `loadSetupStatus` | `packages/shared/src/setup-facts.ts` |
| Design | `src/app/globals.css` (tokens) | `mobile/src/theme` | mêmes couleurs, rayons, ombres, dégradé de marque |

Un client créé sur le web apparaît sur l'iPhone (même table `customers`), un devis
dicté sur le chantier s'ouvre sur le web (`quotes`), l'entreprise modifiée d'un côté
est lue de l'autre (`business_profiles`). Aucune donnée locale simulée.

## 2. Ce qui a été construit dans cette passe

- **Tokens** alignés sur iOS : encre `#0B1220`, accent `#2F52E8`, surfaces `#F5F7FB`,
  ombre de carte courte, dégradé de marque (`.brand-surface`) identique aux arrêts de
  `mobile/src/theme/gradient.ts`.
- **Coque** (`src/components/app/shell/`) : barre latérale (Accueil, Devis, Clients,
  Relances, Prospects · Outils : Catalogue, Analytique, Assistant · bas : Équipe,
  Abonnement, Paramètres, Aide) réductible en rail sur tablette, mémorisée ; barre
  d'onglets mobile identique à l'iPhone (Accueil, Clients, +, Devis, Plus) ; recherche
  ⌘K ; menu du compte avec formule et état ; transition de page.
- **Accueil** : surface de marque, actions rapides, indicateurs, CA à récupérer, vos
  devis, statuts, clients récents, activité, « À compléter » ; premier lancement = un
  chemin vers le premier devis, pas des compteurs à zéro.
- **Devis** : table (recherche, filtres de statut, tri, pagination dans l'URL), menu
  d'actions par ligne (ouvrir, PDF, lien client, suppression confirmée), fiche en deux
  colonnes (document + suivi/client/lien), éditeur existant conservé, création avec
  client présélectionné depuis sa fiche.
- **Clients** : table triable, recherche instantanée, fiche (identité, contact,
  statistiques, devis, activité, notes enregistrées en place), modification en modale,
  suppression confirmée.
- **Paramètres** : colonne de sections (Profil, Entreprise, Abonnement, Équipe,
  Automatisations, Formulaire, Confidentialité et IA, Données et sécurité). Profil :
  nom, changement d'adresse par code, langue, photo, réinitialisation du mot de passe.
  Données : exports JSON, suppression du compte (mot de passe + SUPPRIMER).
- **Abonnement** : droit unifié (formule, état, fournisseur Apple / paiement en ligne /
  essai, échéances, changement en attente), consommation, formules, paiements.
- **États** : `loading.tsx` (squelettes), `error.tsx`, `not-found.tsx`, états vides,
  toasts, confirmations en modale, focus visible partout.
- **Auth** : surface de marque bleue à droite, identique à l'accueil iPhone.

## 3. Stripe — où brancher

Tout est prêt côté serveur ; rien n'est simulé.

| Point | Fichier | État |
| --- | --- | --- |
| Client Stripe | `src/lib/billing/stripe.ts` (`getStripe`, `isBillingConfigured`, `stripePriceId`, `planFromPriceId`) | Activé dès que `STRIPE_SECRET_KEY` existe |
| Tarifs | `STRIPE_PRICE_ESSENTIEL`, `STRIPE_PRICE_PRO`, `STRIPE_PRICE_ENTREPRISE` (`src/lib/env.ts`) | À renseigner avec les identifiants `price_…` |
| Checkout | `POST /api/billing/checkout` → `billingService.createCheckoutSession` | Conserve la fin d'essai, retour sur `/app/parametres/abonnement?statut=succes` |
| Portail | `POST /api/billing/portail` | Moyen de paiement, factures, résiliation |
| Changement de formule | `POST /api/billing/formule` | Montée immédiate, descente à l'échéance |
| Webhooks | `POST /api/webhooks/stripe` (`STRIPE_WEBHOOK_SECRET`) | Met à jour `subscriptions` (plan, statut, période, `stripeSubscriptionId`) |
| Historique | `billingHistoryService.getBillingHistory` | Factures Stripe ou liens Apple |
| UI | `src/app/(app)/app/parametres/abonnement/{page,actions}.tsx` | `PlanActions` s'affiche quand `isBillingConfigured()` ; sinon un espace réservé honnête |

Le modèle de droit est déjà unifié : `toSubscriptionDTO` renvoie `provider: 'apple' | 'stripe' | 'trial'`,
`plan`, `status`, `currentPeriodEnd`, `trialEndsAt`, `pendingPlan`. Le reste de
l'application ne lit que `accessStateFor(...)`. Un abonné Apple a ses droits sur le
web ; un abonné Stripe les aura sur l'iPhone (l'application lit la même session).

## 4. Limites de formule

Les limites sont appliquées côté serveur (`usageService.assertWithinPlan`,
`accessService.assertPlanFeature`, `teamService.ensureTeamAccess`). Le web les
affiche (consommation, verrou Équipe) sans en inventer. `integrations` et
`whiteLabel` sont définis mais aucune fonction ne les consomme encore.

## 5. Vérification

`scripts/captures-web.mjs` capture chaque écran en 1440 / 1280 / 834 / 390 px après
une seule connexion, et signale les erreurs console et tout débordement horizontal.
Le compte de démonstration vient de `prisma/seed.ts` sur une base dédiée
(`devisia_demo`). Les captures de cette passe sont dans
`docs/handoff/captures-web-2026-09-14/`.

## 6. Localisation

Les écrans construits ou refaits dans cette passe lisent le dictionnaire
(`src/lib/i18n/dictionaries/{fr,en}.ts`) et ont leurs clés en français et en anglais.
Les écrans non touchés (relances, prospects, catalogue, assistant, automatisations,
formulaire d'entreprise, contrôles d'équipe) gardent des libellés français en dur :
à migrer au fil de l'eau vers les mêmes sections du dictionnaire.
